# Offline rendering and golden tests

`reverb_render_cli` renders the canonical Barr reference patch to a stereo 16-bit PCM WAV without opening or linking any UI. The same code path supplies deterministic DSP tests and later measurement tooling.

## Build and run

```powershell
./scripts/verify.ps1 -Configuration Debug
build/windows-msvc/src/render/Debug/reverb_render_cli.exe `
  --input impulse `
  --sample-rate 48000 `
  --duration-ms 1000 `
  --output build/reference-impulse.wav `
  --analysis build/reference-impulse.json
```

Accepted inputs are `silence`, `impulse`, and `noise`. The impulse is a unit sample on the left input. Noise is bounded to `+/-0.125`, generated by a fixed xorshift32 seed, and uses a fixed right-channel relationship; it does not depend on the operating system's random source.

The canonical patch is compiled into the engine. It can be exported and explicitly reloaded to exercise saved program/state handling:

```powershell
build/windows-msvc/src/render/Debug/reverb_render_cli.exe --export-patch build/barr-reference.json
build/windows-msvc/src/render/Debug/reverb_render_cli.exe `
  --patch build/barr-reference.json --input impulse --output build/reloaded.wav
```

M1.3 intentionally rejects any document that differs from the canonical reference graph. General patch compilation belongs to M3; accepting a file here must not imply that arbitrary legal schema documents are executable yet.

## Analysis JSON

The optional `--analysis` file, or standard output when it is omitted, contains:

- engine version, sample rate, frame count, and deterministic input name;
- peak floating-point magnitude per channel;
- first nonzero frame per channel (equal to frame count for silence);
- an unsigned decimal FNV-1a hash of each channel after PCM16 quantization.

The WAV writer emits canonical little-endian stereo PCM16 with no metadata or timestamps, so a fixed patch, input, sample rate, duration, and engine version are byte-stable on the primary Windows/MSVC toolchain.

## Golden policy and tolerances

Goldens live under `tests/fixtures/golden/m1-3/`. They are 250 ms at 48 kHz and total approximately 141 KiB. Every sample and channel is compared after PCM16 quantization. The portable tolerance is one PCM16 least-significant bit; the primary toolchain additionally checks exact analysis hashes. A mismatch reports its first frame, channel, expected value, actual value, and difference.

The WAVs are synthesized only from silence, a mathematical impulse, and seeded pseudo-random numbers. They include no third-party recording, ROM data, preset dump, or copyrighted audio asset. See the fixture README for regeneration rules. Golden updates require review of the related engine-version or intentional DSP change.

Reset determinism is checked by rendering, resetting the same prepared engine, and rerendering. Program/state reload is checked by serializing and parsing the canonical graph before rerendering; both channels must be bit-identical as floating-point vectors on the primary toolchain.
